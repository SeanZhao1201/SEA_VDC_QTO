PR-01
Module 1 · Formwork — the problem

Fixed per-floor heights fail on the podium

The first-generation generator assumed one soffit elevation and one “slab below” per floor. That holds on tower levels — and breaks everywhere else. Measured against the exported IFC:

  • Stepped decks get flattened. L02’s soffits span 11'-8" on a single level; 138 of 138 props received the wrong bearing elevation.
  • High-bay voids are invisible. Where L02 has no slab, L03 props were generated at 3'-8" — the ray-verified need is 24–41 ft, reaching down to L01 and even P1.
  • Toppings & partial basements. 54 props stood on structure that does not exist in the concrete model (metal-deck topping zones, SOG-only areas).

Every number above came from replaying the legacy logic against the tessellated IFC and ray-casting the truth — the failure is quantified, not anecdotal.

PR-02
Module 1 · Formwork — the method

Ask the geometry, not the level table

Platforms are built per soffit face, not per floor — stepped and dropped decks keep their true bearing planes, slab openings stay open.

Every prop is a vertical ray fired from the platform underside down through the merged solids of the entire model. Wherever it lands is the foot. Four rules cover reality:

Bearing — skip

Hit closer than 1'-0", or the ray starts inside a wall, column, or same-level downstand beam → no prop needed there.

Normal

Prop generated at the exact ray-measured height — per-location, never per-floor.

TALL — flagged

Taller than 16'-5" (5 m) → generated and tagged for engineered multi-tier shoring. Nothing tall hides in the model.

No support — flagged

Nothing below in the model → grounded at a set grade or skipped with a flag. Never silent.

PR-04
Module 2 · Pour breaks — the input

The approval markups are machine-readable

Pour-break requests live as Bluebeam markups on the structural framing plans (kpff 59-sheet set, one marked sheet per level). Each markup is vector data, so the script reads it directly:

  • Break line — a line annotation across the deck.
  • Paired dimension ticks — the engineer-facing offset to the nearest grid (e.g. grid F − 1'-4½"). The tick geometry and its text agree — self-checking.
  • Option 1 / Option 2 labels — alternatives submitted for approval; Option 1 selected.
  • Measured pour areas — 12,200–18,813 sf polygons, used as validation targets.

All 11 marked levels parsed automatically: P1 and R2 “place whole deck”, L01–R1 carry one Option-1 break each (L01 carries two local segments).

PR-05
Module 2 · Pour breaks — markup to model

Grid ± dimension, then a guarded solid split

1 · Extract

Break lines, dimension ticks, grid bubbles, and pour areas read from the PDF annotations per level.

→

2 · Rebuild grids

No grid objects in the model — axes recovered by clustering 515 column centerlines (grid F alone carries 56) and matched to the sheet’s spacing chain.

→

3 · Position cuts

Cut plane = model grid ± the approved dimension. No PDF-to-model registration to drift.

→

4 · Split & tag

Deck solids split, capped, and tagged POUR1 / POUR2 on suffixed layers.

Tolerance ladder

This model’s file tolerance is 10−5 ft — boolean cuts need slack. The script steps ×10 / ×100 until the section closes.

Volume conservation

Pieces must sum to the original solid within 1% or the cut is rejected. Measured drift on all 18 decks: effectively zero.

Sliver guard

A cut that grazes a slab edge (piece < 1% of volume) is recognized as tangent and reverted — no junk fragments.

PR-06
Module 2 · Pour breaks — a finding the guards caught

L01: the marked breaks are existing slab edges

On L01 both marked breaks coincide — within inches — with edges that already exist in the concrete model: the deck-to-SOG boundary on the north side, and the deck’s east edge at grid B.

The tangent-cut guard refused to force a cut, flagged the condition, and left the decks whole. One small bridging slab genuinely crossing the line was split.

This is the intended behavior: the automation formalizes the engineer’s intent where geometry requires it, and reports — rather than fakes — where it doesn’t.

Status: under VDC review. If the 12" mild-slab zone east of grid B belongs in the deck scope, it can be added to the cut set in one re-run.

PR-08
Recommendations

Modeling practices that make automation cheap

Everything below was reverse-engineered this round. Modeled up front, each one turns a research step into a lookup.

  1. Model the grid. Named lines on a _GRIDS layer with user text (GRID_AXIS=F), exported as IfcGrid. We rebuilt the axes by clustering 515 column centerlines — it worked, but explicit grids remove the single largest inference step for every future script.
  2. Keep layer names semantic and stable. First underscore-segment = element type; keep SOG / TOPPING keywords in slab layer names. Both modules key off these conventions to decide what gets formwork and what gets cut. They held up well — codifying them keeps it that way.
  3. Set a sane file tolerance. 0.001 ft is plenty for concrete; this model was at 10−5 ft. Micron tolerances silently break boolean operations — the L03 deck initially refused to split because of it.
  4. Define floor elevations early (QTO “Set Floor”). Every downstream artifact — quantities, storeys, formwork levels, pour tags — joins on FLOOR. Setting it once up front keeps all vocabularies identical.
  5. Model (or tag) what supports toppings. Topping zones over unmodeled steel/precast produced “nothing below” props until excluded. A layer keyword or a stub of the supporting structure resolves the ambiguity.
  6. Keep pour-break approvals as vector markups with dimension ticks to grids. This round parsed 100% automatically because the markups were clean Bluebeam vectors. Flattened or raster markups would force manual transcription.
  7. Run the QTO checkup before handing a model to automation. Closed, valid solids are what rays and boolean splits rely on; the checkup already exists to guarantee exactly that.
